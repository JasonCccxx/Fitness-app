## 托管打包

- 唯一编辑源仍为 `site/dist`，界面和数据文件保持原样。
- `node site/scripts/prepare-hosted.mjs` 将静态文件复制到根目录 `dist`，适配托管打包入口；该生成目录已忽略。
- `.openai/hosting.json` 保存站点标识及 SPA 深链接回退配置，纳入版本管理，不含密钥。
- Sites 官方 helper 负责 Git 初始化、检查、提交、推送和打包；凭据只经进程标准输入传递，不写入仓库。
- 发布产物只包含静态资源和必要托管配置，不包含 docs、测试或本地服务器。

本机 Node v24.13.0 执行官方打包器的同步目录复制时异常退出；同一复制操作在 Codex 随附 Node v24.19.0 中成功，异步复制也成功。本次官方打包流程使用 v24.19.0 运行，无需修改网页或插件源码。项目仍要求 Node >=22；这条是本机打包环境记录。

## 自行编辑内容与权限

当前可以直接编辑结构化内容文件，再检查、提交和发布；网站还没有内容编辑后台。

若需要在网页里增删改文章或动作，建议 S07 后续增加内容管理后台，或者连接成熟 CMS。管理员登录后，由后端接口验证身份和角色；数据库按所选架构通过受限服务账号或行级访问规则执行约束。不能把数据库管理密钥放进浏览器，也不能只靠隐藏管理按钮保护写入。

管理员应管理内容，普通用户未来只管理自己的训练数据；这两类权限分别设计。当前不实现账号、后台或数据库。

## 自动部署的含义

通常流程为：修改代码 → 本地 commit → push 到指定远端分支 → 托管平台自动运行检查和构建 → 成功后更新网站。可以另外配置分支预览、失败保留旧版与回退。

Git 仓库负责保存代码，托管平台负责运行网站。两者可以连接，但仅创建 Git 仓库不会自动产生网站。本次使用官方工具明确推送并发布，不应把它描述成已经配置了长期的 GitHub 自动部署。
